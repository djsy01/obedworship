### 2026-10-24 — Oracle PM2 배포 및 트러블슈팅

실제 운영 배포 과정에서 발생한 이슈들과 조치 내역.

| # | 증상 | 원인 | 조치 |
|---|---|---|---|
| 1 | PM2로 기동 시 서버가 바로 죽음 (`SyntaxError`) | `routes/ticket-applications.js`에 `[cite: 13]` 같은 인용 텍스트가 실제 코드 문(statement) 뒤에 그대로 섞여 들어가 있었음 | 해당 텍스트 제거, 프론트에서 아직 쓰지 않는 라우터라 `app.js`에서 임시 주석 처리 |
| 2 | `npm start`/`pm2 start app.js` 경로 혼동 | `package.json`의 `main`이 존재하지 않는 `index.js`를 가리킴 | `main`을 `app.js`로 수정, `start` 스크립트 추가 |
| 3 | 프론트에서 CORS 에러 | CORS origin이 `http://localhost:5173`로 하드코딩 | `CORS_ORIGIN` 환경변수로 분리(쉼표로 다중 origin 지원), `.env`에 실제 운영 도메인 설정 |
| 4 | 외부에서 API 접근 불가 | 백엔드가 `localhost:3000`에만 바인딩 | DuckDNS(`obedworship.duckdns.org`)로 도메인 연결 → Nginx 리버스 프록시 → certbot으로 HTTPS 적용 |
| 5 | `obedworship.vercel.app`에서 CORS 에러 재발 | `CORS_ORIGIN`에 실제 프론트 배포 도메인(Vercel)이 반영 안 됨 (`inho.pe.kr`만 설정돼 있었음) | `.env`의 `CORS_ORIGIN`을 실제 Vercel 도메인으로 갱신 |
| 6 | 서버가 기동 즉시 크래시 루프(재시작 200회+) | 보안 패치로 `JWT_SECRET` 하드코딩 기본값이 제거되면서, 운영 서버 `.env`에는 애초에 `JWT_SECRET`이 없었다는 게 드러남 (예전엔 기본값 덕분에 몰랐음) | `openssl rand -hex 32`로 랜덤 값 생성 후 `.env`에 `JWT_SECRET` 추가 |
| 7 | 로고/사진/음원이 Vercel 사이트에서 404 | 백엔드가 파일 URL을 `/files/15` 같은 **상대경로**로 내려주는데, 프론트가 그대로 `<img>`/`<audio>` src에 써서 브라우저가 프론트 도메인(Vercel) 기준으로 찾음 | `config/env.ts`에 `toAbsoluteFileUrl` 헬퍼 추가, 화면 표시 지점(Home/Vision/MainLayout/WorshipDetail/Admin)에서 백엔드 `BASE_URL` 기준 절대경로로 변환.단, `WorshipDetailView`의 `editForm.poster_url`은 저장 시 그대로 백엔드로 재전송되므로 그 지점은 건드리지 않음 |

### 2026-10-24 — 이메일 인증번호 + 비밀번호 강도 검증

- `server/utils/mailer.js`: Resend API로 6자리 인증번호 이메일 발송
- `server/utils/verificationStore.js`: 인증번호를 메모리에 저장(10분 만료, PM2 단일 인스턴스 전제)
- `/auth/send-verification`, `/auth/verify-code`: 회원가입 이메일 인증
- `/auth/forgot-password`: 콘솔에만 찍던 Mock 토큰 방식 → 실제 Resend 발송(6자리 코드)으로 교체
- `/auth/verify-reset-code`: 비밀번호 재설정용 인증번호 확인
- `client/src/composables/usePasswordStrength.ts`: 길이/영문/숫자/특수문자 기준 danger~very-strong 평가, `Register.vue`/`Reset-Password.vue`에 적용 (strong 이상이어야 제출 가능)
